# 帳單出帳（billingVersion 2）

帳務管理先呼叫 `generateMonthlyBills` 的 `preview` 模式，確認後才呼叫 `commit`。
兩者共用 `functions/billing/planner.mjs`，租金與公共分攤公式放在 `rules.mjs`，
Hosting 經由 `src/utils/meter/billing.ts` 重用同一份規則。

## 一致性與重試

- Callable 檢查 Firebase Auth，以及房東／管理員角色與目標房東的資料權限。
- 預覽使用唯讀交易，沒有新增帳單、扣款或寫日誌。
- 確認時交易內重新讀取來源並比對每份租約的預覽雜湊。資料改變即拒絕本批，要求重新預覽。
- 每批最多 400 個寫入、100 份租約，同一租約的帳單與餘額不拆批。
- 帳單使用穩定 ID，租約文件的 billingRevision 也會更新，序列化同時出帳。
- 帳單、預收款扣減、`billing_runs` 重試憑據與 `bill_generate_logs` 在同一交易提交。
- 網路結果不明時保留原 operationId 重試，伺服器回傳已提交結果。變更內容不可重用 operationId。
- 前批成功、後批失敗時保留前批；畫面顯示已確認完成數。重新預覽可接續剩餘帳單。
- 不允許客戶端寫入或刪改 `billing_runs`。部署需要同步更新 Firestore rules。

## 計收規則

- 排除未起租與已過期月份；新租金的整個涵蓋期間不能與既有租金單相交。
- 首末月不足一個月，維持整月計收並在預覽提醒。長週期超出租約終月時暫停該租金，需確認續約或手動處理末期。
- 租金對應以 relatedTenantDocId 優先；只有舊單未記錄文件 ID 時才用登入 uid。多租約共用 uid 的舊單歸屬不明時不自動出帳。
- 電費以房間 ID 與完整租期核對。舊租客有完整租期與房間資訊時可補出其電費；跨租客、跨空房或缺少租期時留待確認，不推估拆分度數。
- 同月多筆不重疊的抄表逐筆出帳；期間重疊或資料無效者略過並提醒。
- 公共分攤逐表向下取整，尾差與空房份額由房東負擔。未能確認歸屬的份額單獨列示，不視為空房。
- 公共表需指定子群組。既有分攤金額或分攤基礎與本次不同時，不混用新舊規則補開。
- 新帳單保存租期、房間、抄表依據或分攤計算快照；分攤摘要記錄於出帳日誌。
- 截止日讀取目標房東設定（預設 12 號），超過月份天數時取該月最後一天；收款日期使用台北時區。

## 查詢與既有資料

為兼容未有標準涵蓋欄位、日期異常但已有 relatedUsageId 的舊帳單，
目前在每次交易讀取該房東全部帳單，不使用畫面的筆數上限或只看近 12 個月。
每一來源查詢超過 20,000 筆時明確拒絕，不靜默截斷。
大型帳戶後續應先建立可回填驗證的租約期間／抄表出帳索引，再縮小查詢；不宜直接套日期上限而失去防重能力。

既有帳單不會自動重算或搬移。手動記帳、改單、刪單與舊版前端仍有原本的操作路徑，
此次交易保證適用於新的自動出帳流程。上線時應要求使用者重新整理舊頁面。

## 驗證與上線順序

```sh
npm test
npm run test:billing:emulator
npm run build
```

模擬器測試硬性要求 demo-billing-review 與 FIRESTORE_EMULATOR_HOST，禁止連正式資料庫。
覆蓋並行出帳、請求重試、日誌衝突回復、預覽失效及 453 筆帳單分批續跑。
需要 Java 21 與 Firebase CLI，測試端口為 18085、18400、18450。

正式上線需先部署新的 `generateMonthlyBills` Cloud Function 與 Firestore rules，
確認 callable 可用後才部署 Hosting。Hosting 單獨更新會因缺少 callable 而無法預覽與出帳。
既有帳單維持原值，不在部署時回填。
